# Dense exploded emblem experiment

Runtime evidence for [#251](https://github.com/DanielssonThomas/Stellar/issues/251), captured in headless Chromium from the production Angular build at 1100 × 760, DPR 1. `comparison.png` pairs the actual 81-plane exploded and settled assembled views. `mid-assembly.png` freezes the actual camera/layer animations at 500 ms; the menu is open to trigger the manual activity. `returned.png` shows the return to idle after dismissal. These are browser captures, not native Windows acceptance or a performance qualification.

The experiment keeps the complete main middle frame and exact settled assembly. Hair uses twelve curved strand groups per color, derived from ImageGen segmentation maps of the original pixels; jewelry separates into twenty leaf regions and two intact gemstone settings. Bodies use eleven wavy organic regions per color. The main ring stays whole; each secondary ring separates into three coaxial arcs at uneven depth gaps. Outer fragment gaps compress toward the stack ends. The original raster and assembled preview bytes remain unchanged; exporter and browser pixel comparisons verify registration at full and supported small sizes. The strand exports and assembled originals total 91 unique runtime images within a 8 MiB experimental budget.

Run `corepack pnpm exec nx run stellar-desktop:serve-static --port=4311` after building, then open `http://localhost:4311`. Use **Experience menu → Start activity** to assemble and **Dismiss** to return. This browser route supports manual visual review without native Ivy or microphone connectivity.

Color separation is verified from actual rendered transforms: all gold body/hair/ornament centers project left of the main ring center and all violet centers project right. Gold body pieces occupy explicit positive depths (530–830); violet character pieces remain at negative depth. Ring and canonical assembly geometry are unchanged by this correction.

The subsequent motion optimization retains all 81 assembly planes, replaces per-fragment float with one gentle stack drift, and retains thirteen independent ring rotations. Both motion helpers batch computed-transform reads before writes. Individual image planes flatten their own 2D contents while camera/drift ancestors retain the shared 3D scene. The updated browser regression verifies fourteen idle animations, zero settled animations, restoration on return, unchanged colors/spacing and exact settled pixels. The captures above predate this shared drift and responsive raster loading.

`motion-profile.json` preserves a single before/after browser profile: headless Playwright Chromium, 1100 × 760, DPR 1, three Start activity/Dismiss cycles, 1150 ms between actions. CDP Performance metrics cover those six transitions; trace events additionally include tracing overhead. Idle animation count drops from 81 to 14, style recalculation count from 1466 to 483, and traced Paint duration from about 731 to 604 ms. The frame-interval p95 stays around 117 ms in this instrumented headless run; no frame-rate gain or native GPU/frame-time qualification is claimed. Results are local observations, not statistical guarantees. Native visual inspection remains separate.
