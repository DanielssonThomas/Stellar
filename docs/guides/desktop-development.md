# Desktop development

`apps/stellar-desktop` is the separate Angular shell; `apps/stellar-desktop-e2e` is its mirrored Chromium project. Both came from the governed application generator. The existing web application and operations dashboard remain separate. The desktop composes the shared interaction controller, local audio activity service, emblem and local Stage through their public APIs. Its startup still initializes the typed app-info adapter and observes the native snapshot event. Installers, signing, updates and autostart remain outside this milestone.

## Windows setup and launch

Install Node 22, Corepack/pnpm, Rustup, Visual Studio Build Tools with the C++ desktop workload and Windows SDK, and the Microsoft Edge WebView2 Runtime. Run `pnpm install --frozen-lockfile` at the workspace root. `rustup show` installs the repository's pinned Rust 1.99.1 toolchain with rustfmt and Clippy. `Cargo.lock` pins native dependencies; Tauri 2.12.5, tauri-build 2.7.4 and ts-rs 12.0.1 are explicitly pinned in manifests.

```sh
pnpm exec nx run stellar-desktop:native-launch
```

This builds Angular, compiles the embedded-content host, and opens `target/debug/stellar-desktop.exe`. Native decorations retain Windows close, minimize, drag, resize, system menu and keyboard behavior. The minimum window size is 480 × 360. Close the window to end the process. The browser-only development server is `pnpm exec nx serve stellar-desktop` at `http://127.0.0.1:4300`; it does not provide native IPC.

The composition root registers thin commands; private `shell` behavior has no Tauri dependency. The native desktop requests microphone capture automatically after the local speech boundary initializes. Browser-only preview retains manual Enable microphone. Denial or device failure uses the existing explicit retry path; Stop microphone remains available. The local main capability grants the read-only `shell_status` and `app_info` commands, the eight fixed Ivy lifecycle commands described below, and event listen/unlisten. App-info emits one snapshot to the local main window when queried. Production configuration has an explicit CSP, no remote capability, no filesystem or shell plugin and no developer tools. Navigation permits only the embedded local origin. Native commands validate deserialized requests and version compatibility.

Angular production builds keep critical CSS external (`optimization.styles.inlineCritical: false`) to avoid its inline stylesheet activation handler under the strict script policy. Tauri supplies a fresh nonce on the static color-scheme style anchor in each embedded response. Bootstrap passes that runtime value through Angular's `CSP_NONCE` token so component styles receive the same authorized nonce; browser development without native CSP uses no nonce. The native smoke checks actual component and utility computed styles, centering, viewport height and nonce propagation. See [Angular's CSP guidance](https://angular.dev/best-practices/security#content-security-policy).

## Contracts and checks

Rust owns IPC serialization. `libs/desktop-contracts` is tagged scope:shared/type:model and exports ts-rs output, generated command/event maps and strict runtime decoders. The governed scope:shared/type:util service-desktop-adapter owns native calls, sanitizes errors and disposes subscriptions, including late registrations. Its browser fake advertises no native capabilities. Change Rust first, run `node tools/native/cargo.mjs contract-generate`, and review the generated diff. `contract-check` fails on drift, including uncommitted changes to generated output.

```sh
pnpm exec nx run-many -t lint test build --projects=stellar-desktop,desktop-contracts
pnpm exec nx run stellar-desktop-e2e:e2e
pnpm exec nx run-many -t native-fmt native-clippy native-test contract-check rust-size-check native-smoke --projects=stellar-desktop --parallel=1
```

Native targets declare Cargo manifests, lockfile, toolchain, Rust/configuration, scripts, generated consumer and architecture policy inputs. Build and smoke additionally depend on the Angular build and its production dependencies. Cargo build outputs live under ignored `target/`; interactive launch and native smoke are uncached. Smoke compiles into a separate `target/smoke/` directory so its additional feature cannot replace the normal host artifact.

`native-smoke` opens a real embedded WebView, waits for the Angular title, invokes the version-one readiness command, verifies its reply and checks rejection of an unsupported version. A compile-time `native-smoke` feature supplies a completion command and a capability overlay only for that test build. It is absent from the normal host command registration. The parent fails after 30 seconds if the WebView does not complete and writes successful results to `artifacts/native/smoke.json`. This is native WebView/IPC evidence, not microphone or installer verification.

The Rust size gate uses syn syntax trees to separate complete exact `cfg(test)` items; strings, braces and comments cannot masquerade as test attributes. Ambiguous conditions count as production. Dedicated test files are counted wholly as tests. Git enumerates tracked and new nonignored Rust sources; no tracked source has an exclusion. Cargo build products and dependency installations are not repository source. Both production and test counts flag decomposition review at 300 physical lines and fail above 500 unless the exact path/category has a reviewed, unexpired registry entry in the [Rust/Tauri architecture rules](../architecture/rust-tauri.md). Registry validation rejects unknown exclusion fields, wildcards, duplicates, missing paths, missing rationale/alternatives/authorization, expired reassessment dates and exceeded ceilings. No exception is approved.

## Extending app-info contracts

App-info uses version 1, snake_case fields, internally tagged capability/error unions and canonical unsigned u64 decimal sequence strings (0 through 18446744073709551615). Never convert a sequence to a JavaScript number. Optional labels accept omitted/null input and serialize as omitted when absent; labels are bounded to 80 UTF-8 bytes. The required build_revision field is nullable and currently null for an unversioned development build. Replies contain at most two distinct known capabilities and no unbounded internal metadata. Rust and TypeScript consume the same JSON fixtures in libs/desktop-contracts/fixtures/.

1. Change the private Rust app_info wire DTOs/domain and command metadata, keeping Stage/audio presentation state in TypeScript. Add bounded typed errors rather than propagating native messages.
2. Run node tools/native/cargo.mjs contract-generate. Do not hand-edit generated.ts. Update runtime decoders and the exhaustive capability consumer alongside new variants.
3. Run the contract-check target: it generates twice, rejects committed-output drift and enables the Rust contract-variant-fixture feature in the exporter to prove a new Rust enum variant fails the real TypeScript exhaustive consumer. The fixture variant is absent from normal builds and its output is never committed.
4. Run model/adapter/frontend tests plus native fmt, Clippy, serialization fixtures and actual native-smoke. Startup exercises the typed adapter, its event subscription and maximum u64 correlation; native smoke also requires a typed malformed-input rejection and selects Sol then clears to Terra through the real IPC commands using an isolated temporary journal, and verifies disconnect stays responsive while rotation waits behind an inert slow operation.

Type generation does not validate runtime data. Native command adapters deserialize untrusted values to DTOs and map malformed requests to a typed error. Frontend decoders reject unsupported versions, variants, extra fields, malformed/nullability values, duplicate capabilities and excessive strings/arrays. Subscriptions are owned by their adapter: stop individual listeners or dispose it when their owner ends; Angular injector destruction handles the injected service.

## Silent Ivy connection

Unresolved Ivy, voice, device, artwork and unexpected interface faults surface automatically as a red exploded emblem with a red-brace error panel. The bounded eight-entry history contains fixed diagnostic messages, local display times, recurrence counts and active/checking/resolved labels; it retains no prompts, raw errors, credentials or private turn identifiers. Device faults direct the user to controls, and artwork/interface faults include restart instructions. Ivy/voice recovery reports progress, waits for an authoritative settled snapshot for at most twenty seconds, then refreshes voice session state. A resolved panel returns to the normal presentation after two seconds; recent history can be reopened from the menu. Expected prompt interruption or a text-fit refusal retains the ordinary composer instead of treating a cancelled draft as application instability. Browser-only preview does not treat the deliberately absent native transport as a runtime fault.

Explicit Connect on an already connected uncertain turn checks its existing receipt. Startup journal contention keeps the worker available: after the original owner exits, explicit Connect retries the exact journal and reloads its retained model and unsettled turn before gateway attachment. It never removes an owner lock or substitutes an empty journal. Terminal receipts must match the retained admission and execution generation, and completed receipts must contain their final response before settlement. Local adapter faults are tracked separately from the last authoritative snapshot, so a successful same-revision read can clear a transient frontend error without admitting an older native state or a late failed request.

The startup adapter connects to the existing personal Ivy gateway without greeting, creating a conversation or submitting inference. Its only startup RPCs are `ping` and `runtime.describe`. A missing gateway produces unavailable/retry state; Stellar does not launch a gateway or change its configuration. Microphone activity is not transcription and never becomes a prompt. Local speech ingress is separate work under #207; this boundary captures, records and uploads no audio.

The fixed Windows installation is `D:/Hermes`, profile `D:/Hermes/profiles/ivy`. Verification used Hermes 0.22.5 at source `bf0203a794a07aac3ff764972ab9087baa4e4f4e`. Native code discovers the managed Python executable from bounded installation facts and launches an embedded attach-only bridge using argument arrays, isolated Python mode and owned stdio. The bridge reuses the installed `IvyConnection`, validates the profile's discovered ready endpoint and calls `connect_gateway(endpoint)` explicitly. Ports are dynamic; none is hardcoded. Hermes obtains its ticket internally through its existing private control channel. Tickets, raw errors, credentials, tool arguments/results and hidden reasoning never enter the renderer contract. Same-user modification of the local Hermes installation remains outside this boundary's isolation guarantee.

Rust owns `ivy_connect`, `ivy_snapshot`, `ivy_submit`, `ivy_cancel`, `ivy_reconcile`, `ivy_disconnect`, `ivy_select_session` and `ivy_clear_conversation`, plus the `ivy-state` snapshot event. Generated types and runtime codecs are exported by `@stellar/desktop-contracts`; `IvyAdapterService` is the frontend invocation boundary. Connection states and turn states are separate: a healthy connection is not an admitted prompt, and an admission or interrupt acknowledgement is not a completed answer. Canonical failed outcomes settle as `failed` with a bounded `turn_failed` code, allowing a later explicit turn; they do not remain permanently uncertain. Empty terminal output produces no presentation item. `revision` is a canonical u64 decimal string; `turn_id` is the caller's stable lowercase UUID. Repeated connects and the same input ID do not submit duplicate work.

A typed selection durably records Terra or Sol intent; repeating the selected intent keeps the foreground session. Clear rotates the foreground and restores Terra intent. Both refuse an unsettled admission, and rotation saves before changing the snapshot. Rotation commands run asynchronously with a bounded wait; disconnect can cancel queued rotation without waiting. A write already started may finish after a timeout, which is reported as uncertain. The snapshot command reports busy until that write settles; retry it before treating the returned model as authoritative. Neither operation deletes gateway history, memories or jobs, or interrupts their work. The browser transport reports these operations unavailable. A legacy session with no recorded route verification is resumed in place on the next explicit turn. Its returned identity and model must match the stored Terra intent before submission; missing or mismatched model information refuses the turn without rotating the session. An unsettled admission must first be reconciled.

On creation, the fixed bridge checks that the gateway advertises model and provider launch parameters, requests only the chosen model and fixed OpenAI Codex provider, and verifies the returned launch request and model before admitting a prompt. A resumed session's reported model must still match. A missing capability or mismatched launch route fails unavailable; the bridge does not choose another launch model. The snapshot distinguishes persisted model intent from a nullable gateway-verified model. This observation is the selected gateway route, not proof of the provider used for a completed inference.

Only an explicit user turn creates/resumes the native conversation. Its text is bounded to 8,192 UTF-8 bytes and receives a fixed presentation-format instruction, with no workspace content or device identifiers. The host retains session/admission identity and observed execution generation. A file lock prevents competing Stellar owners; an atomic local journal stores only those identifiers and unsettled status, not a duplicate transcript or user text. The installed Ivy broker also retains its existing writer/admission exclusion. On disconnection, a native turn can continue: reconnect and explicitly reconcile the canonical session and receipt. No uncertain prompt is automatically resent. A locally queued submission cancelled before dispatch restores the durable unadmitted state; a write-attempted submission retains uncertainty. If admission identity cannot be recovered, the turn remains blocked for inspection. An admission queued without an observed execution generation cannot be safely interrupted through this route. Cancellation is not rollback and stays nonterminal until canonical completion or a terminal receipt confirms its outcome.

Requests are limited to 16 KiB of encoded JSONL and the native incoming queue to 32 frames. Assistant completion text and reply/event frames have no fixed application byte ceiling: the bridge, native parser, generated-contract decoder and trusted assistant-message surface preserve the complete content. Physical memory and upstream gateway/model limits still apply. The bridge has a 15-second RPC deadline, native RPC waits have an 18-second ceiling, and an unsettled turn loses its attachment after 180 seconds with an uncertain outcome. Shutdown or explicit disconnect kills and reaps the owned bridge, not the gateway. No renderer-supplied executable, profile, path, endpoint, generic RPC or approval grant is accepted. The bridge denies approval requests through the existing observed generation fence; interactive approval/clarification handling remains in Hermes.

Ordinary completion text remains plain text and does not open Stage. An exact `stellar_presentation` envelope may request `assistant_message`, with a nonempty plain-text title and body of any length. Stage and the menu scroll long content and wrap long unbroken strings. At most two presentation items are returned: ordinary text and an optional component or close action. Unknown fields/components or malformed envelopes remain literal text. Consumers must use text bindings, never HTML insertion or evaluation. Ivy is instructed to request presentation only when the user asks to show content, and to include all requested information.

To close the current activity when the user asks, Ivy can return `{"text":"Closed","stellar_presentation":{"action":"close_activity"}}`. This becomes the generated `close_activity` item, then validated Stage close commands for the activities retained at submission, including minimized activities. It does not stop the microphone or cancel conversation. Stable turn/revision fences consume the action once; reconciliation cannot close content opened after that request. No generic UI command or executable output is accepted.

During local transcription, assistant response processing and voice synthesis, an additional violet ring with four stars surrounds the assembled emblem. The artwork shrinks to 86% and fades to 68% opacity. Actual narration removes the ring and restores the artwork; completion without narration, cancellation, error and suspension clear waiting as well. The same behavior works with docked content. Reduced motion retains a static star ring and immediate opacity/size changes; hidden/inactive views stop its motion. Displayed replies have no application text limit; the separate local speech synthesis limit remains 4,000 UTF-8 bytes, and longer replies are available as text.

The [source contribution receipt](../../tools/native/evidence/ivy-boundary.json) preserves the first Foreman response that supplied no source and the explicitly authorized recovery call that supplied the bridge and presentation parser. Codex verified actual health responses, added canonical receipt projection, integrated resource ownership and wrote deterministic negative tests. A real silent handshake passed through the Python bridge in 327 ms and through Rust's fixed child transport in a separate explicit test; each sent only ping/describe. No conversation inference was run as qualification, and no speech result is claimed.

`native-test` additionally runs `tools/native/ivy_bridge_test.py` with Python 3.11 in CI. Local developers need Python 3.9 or newer on PATH; the installed Hermes interpreter can be added to the current process PATH without changing global settings. Standard tests use inert children and in-memory gateway fixtures. The actual profile check is deliberately ignored by default and must be selected explicitly:

```sh

```

The native-smoke build enrolls only Ivy selection and clear commands against an isolated temporary journal; it does not enroll connection or submission commands and cannot contact the personal gateway. A normal application's silent startup and subsequent user-initiated conversation still require native/UI acceptance on the final integrated revision; a unit or health-check result is not a real assistant answer.

The #206 menu shows ordinary Ivy text inline. Only completed, explicitly eligible assistant_message items use the validated Stage allowlist; titles and bodies remain plain text. Revision and turn fences prevent stale or closed content from reopening, including expired eligibility during receipt reconciliation. Hidden completion is deferred until presentation is available. Retry only reconnects; uncertain submissions require Check response and are never resent automatically. The current draft remains in the text field after submission so failure does not silently discard the user input.

## Session-scoped workspace tools

The desktop registers rich text (paragraphs, code, lists, checklists and tables), images, constrained node/edge diagrams, browser fallbacks, workflow and session views. Ivy supplies data to registered components; generated frontend code and arbitrary HTML/SVG are not executed. Images accept bundled emblem assets or bounded PNG/JPEG/WebP data URLs. The production CSP forbids frames and remote images, and native navigation is restricted to the application origin. Browser panes therefore show a validated HTTP(S) address and an explicit unsupported-embedding fallback; they do not automate a browser.

Workflow and session panes select real native sources rather than accepting model-authored status values. They show source names, observation age and unavailable fields; stale snapshots do not retain live-looking metrics. Project filters keep global source limitations visible. Pane removal releases subscriptions, and snapshots with errors are unavailable even when the transport remains connected. The local read-only telemetry source must be running separately on its fixed loopback endpoint; its absence is reported without invented replacement values.

All app-originated and Ivy-originated commands allocate from the same Stage sequence. Tool handlers validate payloads with the registered decoders, synchronously recheck foreground ownership and expiry immediately before mutation, and expose only metadata on inspection. Confirmed foreground clear removes retained panes even if the window becomes suspended during reset. Retiring panes preserve their measured geometry and opacity through Angular's leave callback; focus uses preventScroll so an entering off-screen pane cannot scroll the clipped viewport ancestor.

New explicitly created Ivy foreground sessions use a fixed loopback MCP server scoped to that foreground. The bridge checks the gateway's ACP editor-policy and session-MCP capabilities and supplies an allowlisted HTTP descriptor; neither the renderer nor the model can provide a server, executable or RPC method. The per-foreground bearer is stored under an application-owned Windows Credential Manager reference, and the journal contains only that reference and the selected port. Reattachment uses the same port and credential, and fails closed if either is unavailable; it does not rotate history or silently replace the descriptor. A credential created before a subsequent journal failure may remain as an orphaned application-owned entry. Existing CLI foreground sessions remain usable without workspace tools until the user explicitly clears the foreground to create a new session.

The bridge exposes registered pane operations and metadata-only inspection through bounded, correlated requests. The backend creates a fresh per-turn capability, supplies it in the turn instruction, and checks it before emitting a request; it is never included in the renderer IPC. A newly attached server is reported as unavailable until a valid current-turn request confirms the path. Cancel, foreground reset, disconnect and restart invalidate pending tool capability without cancelling or resending an Ivy admission. An already applied Stage operation is not rolled back by a later cancellation. A handler must synchronously check the current turn and workspace generation immediately before mutation; the adapter fetches a fresh snapshot first and checks a native-stamped deadline before mutation. A monotonic renderer clock and a wall-clock consistency check fail closed on elapsed time or observed clock changes. The absolute deadline assumes the system clock stays consistent between observations; a transient clock jump that reverses between checks cannot be detected. Pending requests from an old application process fail closed, while the canonical admission can still be reconciled and a later explicit turn reuses the same foreground descriptor.

Payload JSON is limited to 64 KiB for rich text, image and assistant messages, 16 KiB for diagrams, 4 KiB for browser panes and 2 KiB for workflow/session selectors. The concrete pane decoder applies additional validation. Capture is a separate explicit tool call targeting only the owned main window, with dimensions at most 4096 by 4096 and a maximum 4 MiB PNG, transferred to the private bridge over a separate authenticated ephemeral loopback connection, independent of ordinary bounded control messages. Its short-lived credential is never journaled or sent to the renderer. Captures are not continuous. Hermes normally caches MCP image content as media files for its own use; the user-authorized on-demand image may therefore persist in that upstream cache. No cache path is sent to the renderer.

## Local speech boundary

`tools/native/voice-qualification.mjs` is an explicit synthetic native-app qualification helper. It attaches only to a specified loopback CDP target, requires a matching offline worker/fixture hash receipt and an idle isolated app with an empty Stage, then installs a synthetic-only media source before the operator enables capture. It delegates real native IPC, privately inspects synthetic cleanup input to classify the fixture, and records bounded state, timing, track-end and outcome metadata without PCM, transcript, credential, device or local-path contents. It neither starts the app nor enables capture itself. This is not physical microphone or Windows indicator evidence; a failed hook must be followed by closing the owned app without enabling capture. The helper requires the `--run-synthetic`, `--endpoint`, `--target-id`, `--fixtures`, `--offline-receipt` and `--output` arguments, and creates the output only if it does not already exist.

To reproduce a qualification with an already-running, isolated debug build and privately prepared fixtures, supply the owned target and new output path. Open the native controls with capture disabled first; enable synthetic capture only after the helper prints its readiness message. The fixture receipt must match the installed worker and include the negative, ordinary-speech and silence controls.

```sh
node tools/native/voice-qualification.mjs --run-synthetic --endpoint http://127.0.0.1:10005 --target-id <owned-target-id> --fixtures <private-fixture-directory> --offline-receipt <private-receipt.json> --output <new-output.json>
```

The [synthetic native qualification index](../../tools/native/evidence/desktop-v2-qualification.json) records two historical passing native runs at 1100 × 760 and 2560 × 1370 under the earlier turn-taking implementation. The updated continuous-dictation implementation subsequently passed synthetic native runs at both viewports using an Angular development-mode diagnostic build. Each retained capture during draft recognition and cleanup, then released it before final Ivy and playback; settled public Clear returned Terra idle. Production build and IPC smoke are separate checks. An earlier continuous diagnostic lost a critical negation at an audio boundary; the corrected boundary passed the later runs. Both recognized “send prompt”, refined the draft, submitted once after the presentation closed, reached verified Sol and the requested pane, then passed through Kokoro synthesis and Windows playback to idle and capture reacquisition. The primary run also passed a public foreground Clear API fixture after capture had settled, returning Terra idle and retiring the pane; this was not a spoken Clear test. The prior immediate overlapping stop and reset returned false despite native rotation; it is retained as an interrupted attempt rather than counted as that settled pass. Plain “send” has automated command/coordinator coverage only. The runs use synthetic input and do not establish physical microphone, Windows indicator or performance-budget acceptance; those remain separate in #184.

The unchanged Whisper worker misrecognized one native synthetic “end prompt” as “and prompt”; the “send prompt” fixture passed in the later native runs. “And prompt” must remain ordinary speech. A command-vocabulary hint was rejected because it turned that negative into a false command. These examples do not establish recognition accuracy or performance.

The speech feature uses the selected Web Audio stream. Microphone activity remains distinct from recognition: only a completed nonempty local transcript can reach the existing conversation coordinator, using its stable utterance UUID. The native speech commands never submit a prompt. Startup checks the native speech snapshot and opens microphone capture; it does not load speech models or synthesize a greeting.

Voice invocation is an explicit pipeline stage before session routing. With microphone capture enabled, passive local recognition accepts a leading “Ivy” token or the specific dotted phonetic spelling “I.V”/“I.V.”; ambient speech, “ivory”, possessives and mentions later in a sentence cannot invoke it. Both spellings use the same wake gate, preserve the raw transcript panel, and are ignored as wake commands inside prompt dictation. Bare “IV”, “I mean” and “I think” are not aliases. “Ivy” alone arms the next utterance. “Ivy” followed by a normal request selects Terra; “Ivy, prompt” opens Sol composition and retains any following words as its draft. An active foreground interaction accepts follow-ups without repeating the wake word. Wake eligibility is latched until an explicit completion/reset; quiet and long pauses do not expire it. An open draft also remains active across pauses. Explicit capture stop/loss or a session reset clears invocation eligibility; retained drafts remain available for recovery. Focus loss does not reset it. Typed input remains an explicit invocation.

The gate reuses the installed confidence-filtered [faster-whisper recognizer](https://github.com/SYSTRAN/faster-whisper), with no fuzzy wake-word aliases or recognition vocabulary hint. This reuses bounded local transcription snapshots, not a dedicated acoustic keyword model. During passive speech, wake snapshots begin after 500 ms of active audio, instead of one second. The first exact leading Ivy hit immediately latches foreground presence; a later transcript need not repeat or confirm the wake word. A running wake preview finishes even when quiet queues the full sentence, so an available hit is never discarded in favor of final recognition. Request dispatch still waits for the finalized utterance. This deliberately trusts an early match even if a later recognition would revise it. Passive and ordinary recognition use the existing bounded collection queue while capture continues; normal requests gate recognition during session selection/dispatch and playback while the same capture stream remains open. At most three finalized snapshots wait behind one recognition; overflow stops voice with an error instead of silently dropping speech. A capped continuation cannot introduce a new wake prefix. Wake words inside an open draft remain dictation. No model or dependency is installed. A dedicated detector such as [openWakeWord](https://github.com/dscripka/openWakeWord) would need a trained and qualified Ivy model; it is not bundled. Command dispatch still incurs utterance settlement; wake activation incurs the initial snapshot window and local inference latency. Whisper may misrecognize or hallucinate words, so this gate does not establish smart-speaker latency or acoustic false-accept rates. The [native synthetic qualification](../../tools/native/evidence/wake-invocation-qualification.json) records roughly 1.9–2.1 seconds per recognition on the final run and a 5.9-second first-run observation, excluding silence settlement; these are individual observations, not performance percentiles.

The small bottom-left “Whisper heard” panel displays only the latest raw recognition result, including passive speech, wake previews and finalized requests before wake-word stripping. It updates in place rather than retaining a history, runs no extra recognition or cleanup, and does not indicate that passive speech was dispatched. Empty results leave the latest words visible; stop/reset removes them. Prompt entry discards the displayed transcript, and prompt dictation stays out of the panel throughout composition, refinement and submission, including after cancellation. The panel is hidden while suspended/shut down and is never a focus-taking modal.

Within an active session, whole “prompt” opens a Sol draft; later utterances accumulate across pauses until a whole utterance “end prompt”, “send prompt”, or “send” sends it once. “Clear” and completion phrases (“done”, “that's all”, “I'm done”, “alright I'm done”, including expanded and “all right” forms) request a settled foreground reset to Terra and restore the wake requirement; a refused or uncertain reset retains unsent text. Drafts exceeding the 8 KiB input limit are retained for correction. The app restores model intent from a fresh native snapshot before voice collection and refuses collection while that state is unavailable or unsettled. Model selection is intent; only the separately verified gateway route establishes what the gateway reported. Finalized drafts use the local cleanup adapter described below; ordinary utterances bypass refinement.

While composition is open, a finalized “prompt cancel” command also cancels when it appears at the end of a sentence, optionally followed by a Send command. It takes precedence over accumulation and finalization, discards raw/refined/provisional text, aborts pending draft cleanup and presentation results, and closes the braces with a short exit transition (immediate under reduced motion). Cancellation does not select or reset a native conversation, run a final cleanup pass, or dispatch the draft. Already admitted live cleanup cannot be undone, but its result is fenced and cannot restore or send the discarded draft. The foreground returns to passive listening and requires a fresh “Ivy”. Outside composition, the phrase has no cancellation meaning. Provisional previews may activate wake presence but never dispatch or cancel commands, and phrases such as “explain the prompt cancel command” remain dictation.

Draft recognition uses repeated bounded snapshots of the cached local Whisper model to show a provisional preview; it does not synthesize word-by-word results. Draft segments settle after about 560 ms of quiet following the activity detector's hangover; a pending speech onset resets that countdown before activity is confirmed. Ordinary turns use about 1.4 seconds of quiet. Capture remains active through draft recognition and cleanup, subject to bounded buffering and interruption handling.

Generated `SpeechTranscribeRequest` carries mono 16 kHz signed PCM16, limited to 320,000 samples (20 seconds). The separate speech subprocess frame is limited to 3 MiB; responses are limited to 16 KiB with an eight-frame queue. `speech_transcribe` returns at most 8,192 UTF-8 bytes, including an empty result for no recognized speech. The installed faster-whisper base model runs on CPU/int8 with VAD and confidence filtering. Desktop transcription explicitly sets English (`language: en`) for every snapshot and final utterance, avoiding language guessing on short wake/completion phrases. The shared profile may leave its language unspecified/auto or explicitly use en; other explicit profile languages are rejected by this English desktop boundary. No shared Hermes configuration is modified. An Ivy hotword experiment changed an Ivory negative fixture into Ivy, so no vocabulary boost is added. “I think” and “Und dann” remain ordinary transcripts, never wake or completion aliases. Explicit English reduces language-selection ambiguity but does not guarantee correct recognition of a name or a particular speaker. Loading explicitly requires cached files; missing models produce a controlled error, with no installation, download, cloud provider or fallback. Input samples remain in memory and are not written to disk.

`speech_speak` accepts at most 4,000 UTF-8 bytes and uses the existing fixed local Kokoro/af_heart engine and its dedicated interpreter. Longer replies remain available as text. Synthesis writes only to a native-owned temporary directory, with a maximum accepted WAV of 8 MiB and 90 seconds. The host removes complete and partial WAV output after stopping and reaping the owned process. `speech_stop`, window destruction and application exit cancel owned speech work; they never stop the shared Ivy gateway. Transcription has a 60-second deadline, synthesis plus playback a 120-second deadline. Only one speech operation runs at a time. A failed cleanup retains the occupied operation until cleanup succeeds. Abrupt OS termination can leave a temporary output directory; graceful-stop guarantees do not imply crash-proof deletion.

Playback uses Windows' standard-library [`winsound.PlaySound`](https://docs.python.org/3/library/winsound.html) synchronously in the owned speech process, with filename-only and no-default-sound flags. The installed voice interpreter is Python 3.12.15, where synchronous mode is the default and the later named `SND_SYNC` constant is absent. No playback package is installed and no fallback player or shell command is invoked. Stopping the owned process also terminates its playback; a normal completion explicitly clears the process's waveform playback.

The renderer cannot choose paths, engines, voices, executables or provider commands. Speech state distinguishes transcription, synthesis and playback, and stale operation results cannot replace a new owner. Passive listening and active Sol drafts retain capture during bounded Whisper recognition; Sol draft cleanup also retains capture. Ordinary requests and final Send retain the physical stream and discard recognition input until thinking/playback settles, then wait for quiet before accepting another utterance. Foreground wake state remains independent of this gate. Explicit microphone stop, input changes/failures and shutdown still invalidate stale recognition. The obsolete physical turn-release/reacquisition gate is removed from desktop composition. Voice output mute remains independent from microphone stop. This is a bounded turn-taking voice path, not full-duplex barge-in. Mocked track and browser tests do not establish physical Windows microphone-indicator behavior; that remains part of #184 and #225.

Speech requests and snapshots carry a canonical u64 decimal `epoch`. The adapter reads the authoritative snapshot before initial work and before stopping. An equal-epoch `SpeechStopRequest` advances the native epoch before cancellation; older delayed transcription or synthesis requests are rejected even if decoding starts after Stop returns. A repeated older Stop cannot cancel a newer operation, and a future epoch is invalid. Cleanup failure keeps admission occupied; a retry first reads the current epoch and requests Stop again. Application shutdown permanently seals admission, independently of this reusable Stop protocol. Cancellation and final transcript settlement are ordered under the same native state lock.

Inert-child Rust tests cover stop, stale results, cleanup and process ownership. Actual local-engine and user speech acceptance must be reported separately.

## Local finalized-prompt cleanup

During a Sol draft, the coordinator commits recognized utterances and requests cleanup of the whole accumulated raw draft after each stable segment. One cleanup runs at a time; newer revisions supersede stale results. Standalone “end prompt”, “send prompt”, or “send” finalizes the draft using its latest accepted refinement, or requests cleanup if none is current. Ordinary speech bypasses cleanup. The submitted result uses the refined text or exact raw fallback once, while the composition retains the original in `lastSubmittedRaw`. Its native command accepts at most 8,192 UTF-8 bytes and one active request. An owned Python child resolves the already-running Hermes-managed machine service with its ownership-checked client, requires the fixed loopback endpoint, and sends a no-tool Qwen3.5-9B chat request. Authentication stays inside the child; redirects and proxies are disabled. The service does not start or reconfigure Hermes, although its ordinary router may load the model on demand. The child is bounded to 50 seconds and reaped afterward; window destruction and application exit seal admission and kill and reap an active child; a missing service, malformed response, busy operation, oversized input, failure or timeout returns the exact raw text. Browser-only use falls back without a model.

The frontend retains raw and refined text separately and rejects late results after cancellation. The model receives the transcript as data, and its output is accepted only when it matches the original apart from outer whitespace or a leading comma-delimited “um,” or “uh,” interjection. All other changes, including explicit revisions and capitalization, use the exact raw fallback. Existing path and numeric-identifier checks also remain in place and can conservatively reject ambiguous quotes. This narrow allowlist does not prove general semantic equivalence: a leading interjection can itself be meaningful. Model output remains untrusted and the original transcript remains available for diagnostics. Cancellation fences downstream submission; it does not immediately abort inference already admitted by the shared router. This adapter does not submit prompts or distinguish partial speech itself: the caller must invoke it only for finalized utterances and submit at most once.

The voice coordinator offers an optional abortable presentation handoff after refinement. While its consumer is completing presentation, composition exposes both raw and refined text and reports finalizing; only successful completion permits submission. An unbound handoff preserves immediate submission. Cancellation, unbinding, or a ten-second completion deadline prevents late submission and retains the draft; the deadline reports failure and does not signal that presentation finished. A foreground session selection may already have succeeded before cancellation.

The desktop binds this handoff to `PromptComposerMolecule` for Sol drafts. After the emblem assembles, golden braces open horizontally from a shared center below it, revealing plain white text over a slightly lighter tone. Text reflows and scales down to fit the available area without scrolling; exceptionally long text can therefore become small. Fitting includes the current character-edit frame. If even the minimum measured size cannot fit, finalization fails and retains the draft for a larger viewport instead of submitting clipped text. The source string remains intact. Stage retains existing presentation components and their layout while hiding and making them inert during composition; leaving composition restores those same components and the emblem's usual size. Terra draft submission completes the handoff immediately without opening the Sol composer.

Finalization removes and replaces the changed characters while retaining the common prefix and suffix, then closes the braces back to their shared center as the text and lighter tone disappear. Character edits preserve grapheme clusters and use the rendering clock; brace motion and correction each take one second, followed by a one-second corrected-text hold before closure. Long corrections advance multiple characters per displayed frame. Dispatch awaits the actual Web Animations completion promises and the committed closed render; a duration timer never signals success. Reduced motion commits the same states without movement. Interrupted preparation retains raw and cleaned text, and Clear removes the composer with the foreground conversation reset. Native visual qualification uses explicit draft/recognized-command fixtures with the real cleanup and Ivy boundaries; it does not establish microphone, recognition or physical speaker acceptance. Cleanup preservation is a separate requirement from animation ordering.

A single synthetic local qualification used the existing managed Qwen3.5-9B service with no tools and thinking disabled. It retained `C:\demo\report.txt` and `ALPHA-42`, applied a JSON-over-CSV revision, and completed in 9.99 seconds. This observation is not a guarantee of semantic preservation, latency, model availability, or physical microphone acceptance.
