# Desktop development

`apps/stellar-desktop` is the separate Angular shell; `apps/stellar-desktop-e2e` is its mirrored Chromium project. Both came from the governed application generator. The existing web application and operations dashboard remain separate. The desktop composes the shared interaction controller, local audio activity service, emblem and local Stage through their public APIs. Its startup still initializes the typed app-info adapter and observes the native snapshot event. Installers, signing, updates and autostart remain outside this milestone.

## Windows setup and launch

Install Node 22, Corepack/pnpm, Rustup, Visual Studio Build Tools with the C++ desktop workload and Windows SDK, and the Microsoft Edge WebView2 Runtime. Run `pnpm install --frozen-lockfile` at the workspace root. `rustup show` installs the repository's pinned Rust 1.99.1 toolchain with rustfmt and Clippy. `Cargo.lock` pins native dependencies; Tauri 2.12.5, tauri-build 2.7.4 and ts-rs 12.0.1 are explicitly pinned in manifests.

```sh
pnpm exec nx run stellar-desktop:native-launch
```

This builds Angular, compiles the embedded-content host, and opens `target/debug/stellar-desktop.exe`. Native decorations retain Windows close, minimize, drag, resize, system menu and keyboard behavior. The minimum window size is 480 × 360. Close the window to end the process. The browser-only development server is `pnpm exec nx serve stellar-desktop` at `http://127.0.0.1:4300`; it does not provide native IPC.

The composition root registers thin commands; private `shell` behavior has no Tauri dependency. The native desktop requests microphone capture automatically after the local speech boundary initializes. Browser-only preview retains manual Enable microphone. Denial or device failure uses the existing explicit retry path; Stop microphone remains available. The local main capability grants the read-only `shell_status` and `app_info` commands, the ten fixed Ivy lifecycle commands described below, and event listen/unlisten. App-info emits one snapshot to the local main window when queried. Production configuration has an explicit CSP, no remote capability, no filesystem or shell plugin and no developer tools. Navigation permits only the embedded local origin. Native commands validate deserialized requests and version compatibility.

Angular production builds keep critical CSS external (`optimization.styles.inlineCritical: false`) to avoid its inline stylesheet activation handler under the strict script policy. Tauri supplies a fresh nonce on the static color-scheme style anchor in each embedded response. Bootstrap passes that runtime value through Angular's `CSP_NONCE` token so component styles receive the same authorized nonce; browser development without native CSP uses no nonce. The native smoke checks actual component and utility computed styles, centering, viewport height and nonce propagation. See [Angular's CSP guidance](https://angular.dev/best-practices/security#content-security-policy).

## Contracts and checks

Rust owns IPC serialization. `libs/desktop-contracts` is tagged scope:shared/type:model and exports ts-rs output, generated command/event maps and strict runtime decoders. The governed scope:shared/type:util service-desktop-adapter owns native calls, sanitizes errors and disposes subscriptions, including late registrations. Its browser fake advertises no native capabilities. Change Rust first, run `node tools/native/cargo.mjs contract-generate`, and review the generated diff. `contract-check` fails on drift, including uncommitted changes to generated output.

```sh
pnpm exec nx run-many -t lint test build --projects=stellar-desktop,desktop-contracts
pnpm exec nx run stellar-desktop-e2e:e2e
pnpm exec nx run-many -t native-fmt native-clippy native-test contract-check rust-size-check native-smoke --projects=stellar-desktop --parallel=1
```

Native targets declare Cargo manifests, lockfile, toolchain, Rust/configuration, scripts, generated consumer and architecture policy inputs. Build and smoke additionally depend on the Angular build and its production dependencies. Cargo build outputs live under ignored `target/`; interactive launch and native smoke are uncached. Smoke compiles into a separate `target/smoke/` directory so its additional feature cannot replace the normal host artifact.

`native-smoke` opens a real embedded WebView, waits for the Angular title, invokes the version-one readiness command, verifies its reply and checks rejection of an unsupported version. A compile-time `native-smoke` feature supplies a completion command and a capability overlay only for that test build. It is absent from the normal host command registration. The parent fails after 30 seconds if the WebView does not complete and writes successful results to `artifacts/native/smoke.json`. This is native WebView/IPC evidence, not microphone or installer verification.

The Rust size gate uses syn syntax trees to separate complete exact `cfg(test)` items; strings, braces and comments cannot masquerade as test attributes. Ambiguous conditions count as production. Dedicated test files are counted wholly as tests. Git enumerates tracked and new nonignored Rust sources; no tracked source has an exclusion. Cargo build products and dependency installations are not repository source. Both production and test counts flag decomposition review at 300 physical lines and fail above 500 unless the exact path/category has a reviewed, unexpired registry entry in the [Rust/Tauri architecture rules](../architecture/rust-tauri.md). Registry validation rejects unknown exclusion fields, wildcards, duplicates, missing paths, missing rationale/alternatives/authorization, expired reassessment dates and exceeded ceilings. No exception is approved.

## Extending app-info contracts

App-info uses version 1, snake_case fields, internally tagged capability/error unions and canonical unsigned u64 decimal sequence strings (0 through 18446744073709551615). Never convert a sequence to a JavaScript number. Optional labels accept omitted/null input and serialize as omitted when absent; labels are bounded to 80 UTF-8 bytes. The required build_revision field is nullable and currently null for an unversioned development build. Replies contain at most two distinct known capabilities and no unbounded internal metadata. Rust and TypeScript consume the same JSON fixtures in libs/desktop-contracts/fixtures/.

1. Change the private Rust app_info wire DTOs/domain and command metadata, keeping Stage/audio presentation state in TypeScript. Add bounded typed errors rather than propagating native messages.
2. Run node tools/native/cargo.mjs contract-generate. Do not hand-edit generated.ts. Update runtime decoders and the exhaustive capability consumer alongside new variants.
3. Run the contract-check target: it generates twice, rejects committed-output drift and enables the Rust contract-variant-fixture feature in the exporter to prove a new Rust enum variant fails the real TypeScript exhaustive consumer. The fixture variant is absent from normal builds and its output is never committed.
4. Run model/adapter/frontend tests plus native fmt, Clippy, serialization fixtures and actual native-smoke. Startup exercises the typed adapter, its event subscription and maximum u64 correlation; native smoke also requires a typed malformed-input rejection and selects Sol then clears to Terra through the real IPC commands using an isolated temporary journal, and verifies disconnect stays responsive while rotation waits behind an inert slow operation.

Type generation does not validate runtime data. Native command adapters deserialize untrusted values to DTOs and map malformed requests to a typed error. Frontend decoders reject unsupported versions, variants, extra fields, malformed/nullability values, duplicate capabilities and excessive strings/arrays. Subscriptions are owned by their adapter: stop individual listeners or dispose it when their owner ends; Angular injector destruction handles the injected service.

## Continuous integration

Ubuntu quality checks discover every affected project with an E2E target before installing Chromium dependencies. ## Ivy Reflex

The installed Ivy notebook can opt into local media dispatch receipts with its private `notebook/private/enabled` marker (`ivy-notebook-reflex-v1` plus newline). The native media command writes a bounded spool under that same private directory and wakes the existing notebook worker with a fixed executable and arguments, without a shell or a new scheduled job. Notebook capture disable/pause settings are checked before writes. Only validated explicit Reflex dispatches produce receipts; snapshots and unrelated playback produce none. The receipt preserves requested action, executor outcome, input ID and bounded media context, excluding endpoint identifiers and full snapshots. Current media titles are context rather than evidence of selecting or liking content; pause/skip controls never establish a negative preference. A local notebook failure is independent of the returned action result and never authorizes replay. The spool holds at most 256 receipts and retains unconsumed files at capacity; it reports storage failure without including content.

Reflex is an opt-out beta local interpretation path for everyday desktop requests when a supported installed model is configured. Existing wake, Prompt, Prompt cancel, Done, Clear and foreground controls run first. Admitted ordinary Terra voice requests and typed Terra input use a lightweight native scope check before waiting for Reflex readiness. Only a complete supported local command or current playback-state question enters local reasoning. Unknown content, social conversation, external retrieval, research, multi-action requests, quoted/hypothetical commands and negations delegate once to Hermes unchanged; composed Sol prompts retain their existing dispatch. Ambiguous references within an admitted pane command ask for clarification. A failed or uncertain dispatched action never falls through to cloud execution.

`LocalActionRegistry` in the shared desktop adapter offers request-scoped IDs, descriptions and application-owned executor closures. The model cannot supply tool names, parameters, shell commands or code. The app composes Stage focus/close/minimize/restore/maximize, 25/50/75 percent resizing, adjacent pane moves, layout restoration and session/workflow views using the existing validated Stage. It currently exposes the first eight panes; less specific destinations or unsupported sizes require clarification. New content creation, file changes, application shutdown and arbitrary application launching remain Hermes work. Professional/playful tone is session-local, defaults to Ivy's existing warm professional personality, and can be selected conversationally.

## Local music visualizer

Press **P** outside a text field, or choose **Music visualizer · P** from Experience controls (**M**), to open the audio controls. Listening is off at launch. **Listen to desktop audio** captures the current default Windows playback output with WASAPI loopback, including music from Spotify or other players. This is separate from microphone capture, activity detection and voice recognition. The dialog provides overall, bass, midrange and treble sensitivity sliders from 0–300% and live level meters; changes last for the current app session. Closing the dialog leaves listening enabled.

The private native `music` feature owns the worker, default playback device and sample analysis. The version-1 `music_set_enabled` command accepts only an enabled flag; `stellar://music` emits a status, decimal u64 sequence, four bounded 0–1 levels and a nullable `tone` at approximately 30 Hz. Broad bands use 250 Hz and 2.5 kHz low-pass boundaries and stereo RMS energy. A 4,096-sample Hann-windowed Goertzel bank at 48 kHz selects the dominant note-centered bin across MIDI 36–95, using the higher-energy stereo channel to avoid phase cancellation. This is a visual routing hint, not transcription: chords and harmonics can select a different note, and low notes have coarser resolution. Silence, disabled capture and unavailable audio produce a null tone. Raw playback samples remain transient in native memory and are never persisted, sent to the frontend or uploaded. Frontend decoding rejects incompatible, enlarged or invalid payloads; serialized commands and revision fences prevent stopped listeners from restoring stale levels or tones. Missing frames decay to zero/null after 350 ms.

The controls use the same gold, clipped-corner frame as the activity panels. **Calm**, **Dynamic** (default) and **Flashy** change presentation without resetting sensitivities. Fragments travel outward along their own depth side. Hair and jewelry only increase depth spacing, preserving their distance from the center axis at every intensity; body fragments retain the small high-intensity pull toward that axis. The direction vectors are prepared once per manifest from the same resolved geometry as the ordinary exploded pose. The two secondary ring groups nearest the middle, one on each depth side, expand on bass rises and shrink at a fixed 0.16 scale units per second. Their maximum additional scale is 0.18 in Calm, 0.6 in Dynamic and 0.9 in Flashy, allowing strong hits to expand beyond the farther rings' radial kicks. Higher bass peaks therefore take longer to shrink, and sustained bass alone does not hold them expanded. Farther ring arcs retain their outward-and-return kicks.

Flashy preserves every fragment's original alpha at full element opacity. A resting brightness multiplier of 0.72 darkens the colors. ## Local speech boundary

### Dedicated commands and warm English recognition

The native candidate uses one existing mono 16 kHz PCM capture subscription. `VoiceConversation` copies bounded frames to a persistent CPU keyword worker and assembles conversational audio separately. Passive listening sends no utterances to STT. An acoustic Ivy detection activates the existing foreground state and replays up to three seconds of retained post-keyword audio into the assembler, including audio captured while detection was pending. Wake activation never depends on the spelling returned by a transcriber. No fuzzy wake aliases are accepted.

The fast path uses sherpa-onnx 1.12.40: the English GigaSpeech 3.3M INT8 model and the zh-en 3M chunk-8 FP32 phoneme model. Passive voiced phrases run complementary Ivy-only graphs on both models because the tested voices exposed different misses in either model alone. Ordinary control listening uses only the phoneme model. Neither model decodes idle silence. The phoneme model's multilingual training does not enable foreign-language commands; its graph contains only the fixed English vocabulary. The original small English model missed several controls in replay, while the phoneme model improved prompt cancellation. Eight command search paths improved the tested MCP phrases over four; this does not establish live accuracy. The model adapter remains behind fixed PCM/keyword and PCM/text interfaces; the renderer cannot select models, paths, executables or providers.

KWS applies per-phrase acoustic probability thresholds (Ivy 0.35 in both graphs, controls 0.25), onset and end boundaries, stream continuity and passive/listening/composing gates. A later match must fail the onset gate, and a quieter trailing word remains part of the phrase through a separate continuation threshold. Controls produce a provisional candidate after 240 ms of measured quiet. `recognition-settings.json` under the fixed recognition profile can set integer `command_silence_ms` from 200 through 800; malformed settings fail closed. The coordinator separately waits for 1,000 ms of quiet before acting on a control. Speech resuming before that boundary cancels the candidate; delayed candidates cannot act after newer voiced frames. Discontinuities and public reset fence candidates before dispatch. This deliberately increases control latency because the previous short boundary activated Clear inside paused sentences. The setting changes candidate timing, not the action guard. Wake activation does not use this control guard. No finite silence threshold distinguishes every natural pause from a phrase boundary.

Fast controls reuse the existing done/clear, prompt composition, Hermes context reset and MCP reload routes. Prompt cancel discards a composing draft and fences pending recognition/cleanup without submission. Before the first Sol submission in the current conversation it restores active Terra; after Sol has been used it returns to passive listening. Done/clear return to passive listening after a confirmed clear. MCP reload during composition and the existing send/end-prompt controls retain the finalized-transcript route so queued dictation is not discarded. Active-session KWS misses can still reach that exact whole-transcript command router through conversational STT. This fallback is slower and is not counted as a fast-path detection. Passive misses remain passive.

Conversational STT uses English-only NVIDIA Parakeet TDT 0.6B v2 INT8 through sherpa-onnx's native ONNX runtime, with two CPU threads. No NeMo, PyTorch, CUDA, cloud fallback or language auto-detection is loaded. The native host keeps one transcription process and one keyword process warm, with two bounded response slots each, alongside the existing warm TTS worker. One request is admitted per worker; keyword frames contain at most 640 samples. The frontend bounds queued keyword frames to 64 and fails closed on overflow or gaps. STT retains its 20-second/320,000-sample request limit, 3 MiB input and 16 KiB output frames, 8 KiB transcript limit, epoch fencing and 60-second deadline. Stop, microphone invalidation and shutdown kill and reap owned workers; late results cannot reopen a new session. Models load lazily when their worker first receives audio and remain warm until cancellation or shutdown. Missing assets produce a controlled error, never a runtime download.

Windows speech children use `process-wrap`'s Job Object wrapper, assigning the suspended launcher before it can start the real inference interpreter. Stop and normal Rust drop terminate and wait for the complete job, including descendants after the launcher exits. Inert tests cover both cases, and the installed-engine probe checks launcher and interpreter removal after Stop. The adapter adds no handwritten unsafe code. This is normal lifecycle qualification, not a crash-proof kill-on-close claim. Resource measurements sum the launcher and recursive descendants; measuring only the virtual-environment launcher's small working set understates inference memory. Summed RSS can count shared pages more than once.

Ordinary speech uses 800 ms of assembler quiet after a 600 ms VAD hangover, compared with 1,400 ms plus hangover previously. The native recognition path reuses `ActivityDetector` with speech-specific minimum onset/off RMS of 0.003/0.0018 and an 80 ms minimum active interval, seeded from the existing capture noise calibration. The visual activity meter is unchanged. This gate also processes retained post-wake audio; quiet user requests previously failed the visual meter's higher onset threshold. The assembler's `silenceMs` and separate `draftSilenceMs` options are bounded independently; voice ports can override ordinary timing for qualification. Pending onsets reset either countdown. Prompt dictation keeps its 540 ms assembler threshold, 20-second continuous segmentation and pre-roll. Exact finalized “prompt cancel” can use STT fallback; a preview cannot cancel a draft. Draft previews run at most every two seconds and finish before a queued final instead of cancelling shared recognizers. Recognition is suppressed during ordinary admitted turns and playback, using the existing capture lifecycle; this adds no second microphone listener and does not change emblem styling or model/session selection.

Validated completed prose is segmented at conservative sentence boundaries, combining short fragments. The renderer cannot submit incremental raw model deltas; malformed structured replies, code envelopes and internal reasoning tags remain visible as text without narration. ## Local finalized-prompt cleanup

During a Sol draft, the coordinator commits recognized utterances and requests cleanup of the whole accumulated raw draft after each stable segment. One cleanup runs at a time; newer revisions supersede stale results. Standalone “end prompt”, “send prompt”, or “send” finalizes the draft using its latest accepted refinement, or requests cleanup if none is current. Ordinary speech bypasses cleanup. The submitted result uses the refined text or exact raw fallback once, while the composition retains the original in `lastSubmittedRaw`. Its native command accepts at most 8,192 UTF-8 bytes and one active request. An owned Python child resolves the already-running Hermes-managed machine service with its ownership-checked client, requires the fixed loopback endpoint, and sends a no-tool Qwen3.5-9B chat request. Authentication stays inside the child; redirects and proxies are disabled. The service does not start or reconfigure Hermes, although its ordinary router may load the model on demand. The child is bounded to 50 seconds and reaped afterward; window destruction and application exit seal admission and kill and reap an active child; a missing service, malformed response, busy operation, oversized input, failure or timeout returns the exact raw text. Browser-only use falls back without a model.

The frontend retains raw and refined text separately and rejects late results after cancellation. The model receives the transcript as data, and its output is accepted only when it matches the original apart from outer whitespace or a leading comma-delimited “um,” or “uh,” interjection. All other changes, including explicit revisions and capitalization, use the exact raw fallback. Existing path and numeric-identifier checks also remain in place and can conservatively reject ambiguous quotes. This narrow allowlist does not prove general semantic equivalence: a leading interjection can itself be meaningful. Model output remains untrusted and the original transcript remains available for diagnostics. Cancellation fences downstream submission; it does not immediately abort inference already admitted by the shared router. This adapter does not submit prompts or distinguish partial speech itself: the caller must invoke it only for finalized utterances and submit at most once.

The voice coordinator offers an optional abortable presentation handoff after refinement. While its consumer is completing presentation, composition exposes both raw and refined text and reports finalizing; only successful completion permits submission. An unbound handoff preserves immediate submission. Cancellation, unbinding, or a ten-second completion deadline prevents late submission and retains the draft; the deadline reports failure and does not signal that presentation finished. A foreground session selection may already have succeeded before cancellation.

The desktop binds this handoff to `PromptComposerMolecule` for Sol drafts. After the emblem assembles, golden braces open horizontally from a shared center below it, revealing plain white text over a slightly lighter tone. Text reflows and scales down to fit the available area without scrolling; exceptionally long text can therefore become small. Fitting includes the current character-edit frame. If even the minimum measured size cannot fit, finalization fails and retains the draft for a larger viewport instead of submitting clipped text. The source string remains intact. Stage retains existing presentation components and their layout while hiding and making them inert during composition; leaving composition restores those same components and the emblem's usual size. Terra draft submission completes the handoff immediately without opening the Sol composer.

Finalization removes and replaces the changed characters while retaining the common prefix and suffix, then closes the braces back to their shared center as the text and lighter tone disappear. Character edits preserve grapheme clusters and use the rendering clock; brace motion and correction each take one second, followed by a one-second corrected-text hold before closure. Long corrections advance multiple characters per displayed frame. Dispatch awaits the actual Web Animations completion promises and the committed closed render; a duration timer never signals success. Reduced motion commits the same states without movement. Interrupted preparation retains raw and cleaned text, and Clear removes the composer with the foreground conversation reset. Native visual qualification uses explicit draft/recognized-command fixtures with the real cleanup and Ivy boundaries; it does not establish microphone, recognition or physical speaker acceptance. Cleanup preservation is a separate requirement from animation ordering.

A single synthetic local qualification used the existing managed Qwen3.5-9B service with no tools and thinking disabled. It retained `C:\demo\report.txt` and `ALPHA-42`, applied a JSON-over-CSV revision, and completed in 9.99 seconds. This observation is not a guarantee of semantic preservation, latency, model availability, or physical microphone acceptance.
