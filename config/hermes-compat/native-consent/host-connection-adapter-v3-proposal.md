## Permitted source slice

Implement an uninstalled private `_ConnectionPlan` transaction coordinator, explicitly DATA fixture/composition with no authentication claim. Its constructor captures the original connection OBJECT reference, canonical deep-frozen Context/Prepared and two clocks. No supplied Context becomes authority. The only public operational factory, `attach(...)`, unconditionally raises `host_connection_unavailable`; there is no switch, fallback, callable verifier or positive constructor exported by that factory. Private source is deliberately reachable to cooperating code/tests. Python privacy is not a security boundary against same-user code tampering.

A future positive factory needs separate review and the actual guardian launch/pipe/OS-callback registry. It must retain original authenticated canonical connection and authority objects/epoch, native lease/generation, original session/physical/profile/route/producer/incarnation, policy revision and callback association. Every positive operation must revalidate actual capabilities before AND inside its canonical transaction. This data plan cannot do that and must never create Attachment, Verification, GrantIntent or HostConsumeSuccess. A callable returning true does not supply the capability.

Each operation requires the exact retained object (`is`, never `==`) and fresh Context/Prepared DATA matching the frozen snapshot. Tests supply explicitly synthetic objects/data; a future private adapter would supply them from the actual registry, never renderer input. Wall/monotonic readings must not decrease. Expiry is bounded by the original challenge and initial monotonic interval, never extended. Changed object/scope/policy/clock seals local positive eligibility. A fresh plan cannot bypass the permanent journal latch. No recovery/rehydration factory exists.

Both clocks return exact nonnegative safe-range Python `int` milliseconds; bool, floats (including NaN/infinity), negatives and overflow refuse. Constructor pins monotonic challenge deadline from its initial wall/mono sample. record_ticket additionally pins an earlier nonextendable monotonic ticket deadline from deadline minus wall at that same sample, capped by original challenge deadline. Read fresh samples inside callbacks and before publishing results; rollback seals. Never substitute binding.createdAt for now. Tests include stalled wall time with advancing monotonic time crossing both challenge and earlier ticket deadlines.

## Exact private call sequence

These are DATA composition, not RPC/live APIs. Exactly one positive operation may be in flight. A short lock reserves an operation/generation BEFORE canonical writer entry without advancing its committed phase. A concurrent positive operation refuses/seals before DB entry. Only a known successful writer return followed by a generation/deny recheck publishes the next committed phase or result. Cancel remains independently available. Use write_once/OneShotWriter around the ENTIRE callback and permanently seal on exceptions/lost ACK/phase conflict. No retries/resend/inspect-to-resume/new challenge. A committed return is data, not native proof. Raw fixture ticket is transient, never persisted/logged.

1. `reserve(original, context, prepared)` writes reserve_on and permanent latch, returns a Prepared copy only after writer return.
2. `begin(...)` writes begin_on before any future OS request; this code invokes none.
3. `reserve_issue(..., intent_id)` writes reserve_issue_on before any future host effect. Intent ID is DATA, not genuine GrantIntent.
4. `record_ticket(..., intent_id, ticket_data, deadline)` hashes bounded lowerhex64 ticket DATA, writes record_ticket_on, retains raw value transiently. No ticket creation or Host.approve call.
5. `release(...)` writes reserve_release_on BEFORE returning ticket DATA once; local state is spent before I/O. Unknown writes/dropped reply never permit replay. Cancel can leave bytes in flight, but bind after cancellation must refuse.
6. `bind(..., ticket_data)` requires released phase, original object/snapshot/hash and reserves consumed locally. Construct a fresh Ledger inside the real writer transaction, using a transaction-local one-shot writer facade. Choose revision in that transaction. The Ledger gate checks DATA scope/fresh clocks; the eventual actual private host gate is additionally required. Fresh \_on_bind calls consume_binding_on so binding, owner and journal state commit together. Return binding DTO after writer return, never HostConsumeSuccess.
7. `cancel(original)` remains independently available while a positive write waits. Set sticky local deny under short lock before write_once/cancel_on/exact existing \_revoke_on. It may use retained original Context after expiry/scope loss but still requires original object. Cancel-first blocks later positive transitions; bind-first atomically reserves revocation obligations. Return obligations DATA, never physical-stop proof; #299 retains exact effect adapters.

No lock spans DB/transport/OS I/O. Cancellation between final check and commit is ordered by canonical writer: bind-first must later revoke with obligations. Local deny withholds positive results after observed cancellation. Unknown commit remains uncertain even if later cancellation succeeds. Dropped objects stay spent via retained DB latch.

Existing Ledger.bind takes a supplied revision; old Host.bind chooses it outside the writer. Do not modify that route. Plan-local composition uses real SessionDB write_once; inside its callback choose revision and invoke existing Ledger.bind through a transaction-local facade permitting exactly ONE callback without nested BEGIN/commit/retry. No facade escapes. Its \_on_bind gets fresh clocks and composes journal consumption. Any repeated/nested facade write refuses. No schema/settings changes.
